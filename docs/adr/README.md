# Architectural Decision Records

Each ADR captures a design decision, the alternatives considered, and the
consequences accepted. Format follows Michael Nygard's template.

## Index

- ADR 0001 — SPA + separate API (Phase 1)
- ADR 0002 — Vite as the frontend build tool (Phase 4, Day 51)
- **ADR 0003 — Defer React Server Components (Phase 4, Day 67)**

## When to write one

Write an ADR when a decision:

- Changes an entire subsystem's technology.
- Is expensive to reverse (weeks of work).
- Will be questioned again in 6+ months if not written down.

Do NOT write ADRs for pull-request-level choices — those go in the PR
description.
